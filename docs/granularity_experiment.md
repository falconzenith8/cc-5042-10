# 显示列表实验：更新粒度的两种方案

本文件是"按节点脏标记"与"按绘制区域传播"两套更新方案的仓库内实验结论。
所有数字都由代码复算，不接受手填：

```bash
python3 -m flowkern.granularity_experiment     # 或 python3 -m flowkern.cli granularity
```

运行后生成 `demo_out/granularity_results.json`（逐对象、逐步的原始数据）、
`demo_out/granularity_report.md`（自动排版的对照表）以及每场景每策略的 PPM
证据与独立整帧参考图。单元测试 `tests/test_updaters.py` 对同一组数据做
断言，报告里的任何数字都能被重新运行覆盖，无法用默认值遮错。

## 1. 两个原型接到同一份显示列表

两个原型都只消费 `displaylist.build_display_list(scene, transform)` 的
`DisplayEntry` 输出，绘制顺序仍只由 `(z, id)` 决定，任何一方都不引入自己的
命令集或重排顺序（`flowkern/updaters.py`）：

| 原型 | 类 | 失效输入 | 重放方式 |
| --- | --- | --- | --- |
| 节点脏标记 | `NodeDirtyUpdater` | 被标记对象 id 集合 + 旧包围盒 | 依赖扩展决定脏区，clip 内按全局顺序重放所有相交条目 |
| 朴素节点脏标记（负对照） | `NaiveNodeDirtyUpdater` | 仅被标记对象 id + 旧包围盒 | 只重放被标记条目自身，不做任何扩展 |
| 绘制区域传播（生产模型） | `RegionPropagationUpdater` | 受影响对象的旧+新设备包围盒 | 合并成脏矩形，clip 内重放整个显示列表 |

负对照不是稻草人：它精确实现了"只重画脏位被置上的节点"这一最直觉的方案，
用来暴露该方案在透明重叠、移动残影、文字外溢下的结构性错误。

## 2. 透明重叠为什么必须检查依赖

源上 alpha 混合不满足结合律，绘制顺序又是结果的一部分。当一个位于下层的
对象被改，盖在它上面的半透明对象即使自身没改，也必须按原顺序重新混合，
否则像素停留在旧颜色。实验的 `translucent_overlap` 场景用三层半透明节点
叠在一个不透明底座上量化了这一点：

- 朴素节点脏标记只重画被标记对象，累计 178,110 px 与整帧参考不符；
- 带依赖扩展的节点脏标记与区域传播都把相交的上层条目纳入重放，逐像素一致。

依赖规则（`NodeDirtyUpdater.update`）：任何与被标记条目包围盒相交、且绘制
序不低于最早被标记条目的存活条目，都并入重绘集；移动/删除留下的旧包围盒
（residue）同样拉入所有相交的存活条目。

## 3. 用移动大节点和编辑细小图元比较工作量

下表是 `granularity_report.md` 的场景汇总（视口 1120×460 = 515,200 px，
累计跨全部编辑步）。`painted_px` 是栅格器真实统计的触达像素，不是脏区估值。

| 场景 | 策略 | 脏区/步占比 | 实际绘制 px | 全量退回 | 像素不符 |
| --- | --- | --- | --- | --- | --- |
| big_node_move（大节点+连线，16 步） | 节点脏标记 | 79.40% | 10,262,254 | 10 | 0 |
| | 朴素负对照 | 20.57% | 2,111,845 | 0 | 3,516,286 |
| | 区域传播 | 21.79% | 3,466,552 | 2 | 0 |
| tiny_primitive_edit（细小图元，15 步） | 节点脏标记 | 55.68% | 8,674,249 | 3 | 0 |
| | 朴素负对照 | 13.23% | 1,279,757 | 0 | 1,947,845 |
| | 区域传播 | 13.23% | 2,632,240 | 0 | 0 |
| translucent_overlap（5 步） | 节点脏标记 | 80.60% | 1,632,046 | 4 | 0 |
| | 朴素负对照 | 6.85% | 645,308 | 0 | 178,110 |
| | 区域传播 | 6.85% | 1,230,304 | 0 | 0 |
| isolated_opaque（4 步，无重叠） | 节点脏标记 | 2.21% | 173,148 | 0 | 0 |
| | 朴素负对照 | 2.21% | 173,148 | 0 | 0 |
| | 区域传播 | 2.21% | 173,148 | 0 | 0 |

读法：

- **局部细小编辑**：区域传播与节点脏标记都能把脏区压到视口的 ~13% 或更低，
  且逐像素正确；区域传播不需要维护依赖集，代价是 clip 内多扫描显示列表。
- **移动大节点**：大节点的旧+新包围盒加上相连连线，脏区天然很大；节点脏
  标记的依赖扩展在密集网格里频繁触及 50% 条目阈值而退回全量（16 步里 10 次），
  区域传播只在脏区真的超过 60% 时退回 2 次，工作量明显更小且同样正确。
- **透明重叠**：朴素方案最省像素但结果错误；两种正确方案都为依赖付出重绘。
- **隔离不透明**：这是朴素方案唯一成立的前提，三者面积与像素完全一致，
  证明节点脏标记的额外机制在无依赖时不产生浪费。

## 4. 什么情况下退回全量绘制

回退不是隐式行为，阈值是 `updaters.py` 的命名常量，每次回退都写入
`UpdateResult.fell_back/fallback_reason`，实验报告逐行打印，无法藏在普通
数字里：

1. 合并后脏区面积 ≥ 视口的 `FALLBACK_DIRTY_AREA_RATIO`（60%）——局部重绘
   已不省像素，clip 重放反而更贵；
2. 脏矩形数量 ≥ `FALLBACK_DIRTY_RECT_COUNT`（12）——碎片化使 clip 切换与
   显示列表扫描的固定成本超过一次整帧；
3. 节点脏标记的依赖扩展集 ≥ 显示列表条目的 `FALLBACK_DEPENDENT_RATIO`
   （50%）——标记方案已退化为"几乎全标"，不如直接整帧；
4. 缩放（scale 变化）使所有 `(id, version, scale)` 缓存键失效，生产内核
   `RenderKernel.set_scale` 直接整帧失效并清空缓存。

生产内核 `RenderKernel` 沿用同一思路：缩放整帧、平移走像素滚动只重绘暴露
条带，其余按合并脏区局部重放。

## 5. 待验证假设（单列，不与结论混写）

以下是本实验据以设计、但尚未在更大规模或真实交互数据上证实的假设，保留
为待验项，后续应以同一套"重绘面积 + 逐像素对照"复算：

1. **60% 面积 / 12 矩形 / 50% 依赖**三个阈值在 1120×460、数十~上百对象的
   场景下合理；超千对象或超大视口下最优阈值可能漂移，需要补压力场景标定。
2. 区域传播 clip 内"扫描全部条目做相交测试"的 O(n) 成本，在对象数远大于
   脏区面积时可能反超空间索引方案；当前规模下 `painted_px` 主导，扫描成本
   可忽略，但没有上千对象的实测数据。
3. 朴素节点脏标记仅在"包围盒互不相交的纯不透明对象 + 静态等长编辑"下正确；
   真实矢量编辑几乎总会有文字外溢、阴影外扩或连线，假设该前提稳定成立本身
   存疑，需要真实编辑会话样本验证其出现频率。
4. 依赖扩展目前用包围盒相交做保守 over-approximation，可能把实际像素不重叠
   的对象也纳入；用精确像素覆盖（coverage）替代包围盒能否进一步降面积，
   未实测。
5. 平移的 `Surface.scroll` 复用与本实验的静态视口模型不同，滚动路径的收益
   未纳入本次粒度对照（仅由 `tests/test_kernel.py` 的平移测试覆盖）。

## 6. 保留式绘制的生产接点与界面启动

原型不是孤立脚本，两条生产接点都已接通，由保留式内核驱动控件：

- **生产内核**：`editor.Editor` 仍以 `renderer.RenderKernel`（区域传播模型）
  驱动全部窗口操作；新增 `Editor.verify_against_full_frame()` 在独立表面
  重算当前场景并逐字节比对，`Editor.compare_update_strategies(edit)` 在场景
  副本上回放同一编辑、并行跑三个更新器返回面积与像素证据，不触碰生产表面。
- **无头矢量编辑窗口**（无显示服务器即可运行，本仓库环境即用此路径验证）：

  ```bash
  python3 -m flowkern.headless_window
  # 交互命令里：
  #   vdrag <id> <x1> <y1> <x2> <y2>  真实拖动后自动整帧像素核对
  #   verify                           任意时刻逐字节对照独立整帧
  #   granularity [id dx dy]           现场比较两套更新策略的面积与像素
  ```

  实测 `vdrag 3 640 70 700 120`：脏区仅 (404,52)-(974,249) 共 112,290 px
  （21.8% 视口），`verify` 报告 PIXEL-IDENTICAL，流程图内容与脏区都有执行
  证据，而非只看实验文本。
- **Tk 矢量窗口**（装有 tkinter 且有显示的机器）：

  ```bash
  python3 -m flowkern.tk_window
  ```

  新增 `verify pixels` 与 `granularity` 按钮，每次松开拖拽都会自动做整帧
  像素核对；失败经 `EditorError` 回到 `_guard`，在状态栏与弹窗以
  retained-draw error 反馈，不会静默。

## 7. 失败如何反馈回保留式内核

- 实验层：任何非朴素策略出现像素不符、或朴素策略的不符与场景预期不一致，
  `granularity_experiment.run()` 收集进 `failures` 并以退出码 2 失败，
  同时写出 `_bad` 判定所需的逐步 mismatch 数。
- 窗口层：`verify_against_full_frame` 返回 `pixel_mismatch` 计数；Tk 与
  无头窗口在非零时走 `EditorError` / `[retained-draw error]` 通道，与既有
  非法操作的错误处理完全一致。
- 测试层：`tests/test_updaters.py` 断言两套生产策略在所有场景所有编辑步
  mismatch 恒为 0，回退必带原因，朴素策略只在隔离场景为 0。
